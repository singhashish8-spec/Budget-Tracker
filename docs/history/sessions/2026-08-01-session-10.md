## What happened

Opened with a pure documentation PR: `docs/repository-study.md`, a
structural map of the codebase — layers, dependency direction, the
migration-safety guard, the OTA/APK release split, and a list of real gaps
(no tests, no CI on PRs, and the AI-scanning docs contradicting both each
other and the actual code) (#47). **This PR was never merged** and still
isn't as of 2026-08-15 — see `findings.md` and `roadmap/decisions.md`.

Design work followed: four new visual skins — Clay (claymorphism), Soft
(neomorphism, deliberately keeping text at full contrast rather than
blending it into the shadow-carried surfaces, "the usual way neomorphism
fails accessibility"), Liquid Glass (real SVG-filter edge refraction plus a
gyroscope-tracked specular highlight), and Spatial (3D parallax with
counter-rotating cards) — behind a tiered "depth engine" that auto-detects
device capability (`deviceMemory`/`hardwareConcurrency`) and never changes
layout, only visual cost (#48). While preparing to ship it, a serious,
already-live bug was found and **split into its own PR to ship first**:
`importBackup()`'s transaction INSERT declared 15 columns but supplied 17
values — present since side-hustle mode (PR #42), silently reducing every
restore to "categories only, everything else gone" (#49) — see
`findings.md`. The same PR added a capped on-device error log, specifically
because 16 of the codebase's 74 `catch` blocks swallowed errors with nothing
but a comment, which is exactly how the restore bug went unnoticed for so
long.

With reliability fixed, the skins shipped, and the very next PR found
they'd introduced a real performance regression: the Liquid Glass specular
was animating `box-shadow`/`background-position` — paint properties — every
frame the phone tilted, "the exact opposite of what the depth engine
should do." Fixed by moving the tilt effect to `transform`-only, and added
a measured (not assumed) frame-rate cap since JS can only ever *reduce*
the render rate, never raise it (#50). Next, a same-day-reported lockout:
turning on Spatial left users with no way to navigate or reach Settings —
root-caused to `perspective` on `.app-shell` making it a containing block
for every `position: fixed` descendant, throwing the tab bar and menu
button thousands of pixels off-screen once a page had scrollable content
(the earlier review only checked a short, non-scrolling page) (#51). Fixing
an audit item (an invisible confirm-dialog on the two glass skins) surfaced
a second bug in the same investigation: every card's rim-light highlight
had never rendered on Liquid Glass or Spatial since #48 shipped, due to a
CSS specificity tie resolved by source order (#52) — see `findings.md` for
both.

The remaining UI/UX audit items shipped in three risk-tiered batches: eight
low-risk CSS/component-only fixes — asymmetric press feedback, composite-
only switch animation, a search-clear button, shared `ProgressBar` usage,
tone-coloured toasts, custom category colours, animated onboarding, and tab
bar icons with a sliding indicator (#53); then the three gesture-heavy items
needing real drag/measurement logic — swipe-to-act rows, pull-to-refresh,
and a properly-measured sliding segmented control (#54); then the final
four, including a FAB-to-sheet shared-shape morph and a long-press
quick-action menu. While verifying long-press against the real component,
found that swipe-to-act's own `onPointerDown` (#54) called
`setPointerCapture` unconditionally, **silently breaking tap-to-expand for
every transaction row in production** since 1.5.5 — fixed and shipped
immediately as a standalone hotfix (#57) before being folded back into the
batch-4 branch (#56) — see `findings.md`. In between, `docs/PROJECT_HISTORY.md`
was created as a single-file catch-up doc (#55) and then updated to cover
through 1.5.7 and the pointer-capture hotfix (#58).

## What the owner asked/reported

| What was asked/reported | Outcome |
|---|---|
| (reported) turning on the Spatial skin left no way to change screens or reach Settings | Root-caused to `perspective` making `.app-shell` a containing block for fixed descendants; fixed by moving the projection to a per-card transform (#51) |
| (from the interaction audit, item #09) the delete-confirm dialog was nearly invisible on two skins | Root-caused to a background token meant for near-transparent washes, not dialog surfaces; fixing it surfaced the rim-light specificity bug (#52) |
| (found mid-session, not user-reported) restoring a backup returned only categories | Root-caused to a column/value-count mismatch in `importBackup()`, present since #42; fixed and shipped ahead of the skins work (#49) |

## What's still pending

- PR #47 (`docs/repository-study.md`) remains open and unmerged.
- PR #48's own body is explicit that real on-device frame rates at the
  `max` depth tier on a mid-range Android phone were never verified, and
  says plainly that if `max` proves too ambitious the honest fix is
  lowering the auto-detect threshold, not softening the effect for everyone.
- Deliberately dropped, not deferred: the edge-swipe-back gesture item from
  the UI/UX audit — Android's own predictive-back gesture already covers
  it system-wide.
