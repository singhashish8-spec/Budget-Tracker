## What happened

Directly follow-on from Session 12's documentation restructure. The owner
asked for a plain-English rundown of everything wrong with the app (bugs,
glitches, loose ends) and the roadmap, then said: *"first fix up
everything broken....no loose ends.."* This session worked through every
item Session 12's `status.md` had flagged as open, verifying each one
against real code/PR diffs rather than acting on the earlier session's
inference alone.

**PRs #34 and #37 (Jules), triaged for real.** Session 12 had logged these
as "likely superseded, not confirmed." This session pulled both PRs' full
diffs and compared them line-by-line against current `main`: every fix in
both — the `sql.js` pin, the CSV-injection regex, the DB connection-
consistency check, even the feature-branch additions in #37 — is present on
`main` today. Closed both on GitHub with the diff evidence in the closing
comment. See `findings.md`.

**PR #47 (repository study), closed as superseded, not merged verbatim.**
Its content lives on in `roadmap/architecture.md` (recovered and updated in
Session 12) — closed with a pointer to that file as its successor.

**The `.env.example`/README AI-scanning drift, fixed.** `.env.example` now
states plainly that no environment variables are needed; the README's
"Configuring the placeholders" section was rewritten to match, along with
two other stale README claims found in the same pass — a "SQLite is not
yet encrypted... before shipping" note that had it backwards (encryption
was deliberately *removed*), and a "CSV injection: not built yet" note for
a guard that's been shipped and working for a while. The README's entire
"Status: MVP core" section, which still listed most of the app's actual
current feature set as "deferred," was also rewritten.

**A stale-copy bug found while fixing the above, not on the original list.**
Checking `roadmap/architecture.md`'s "No faked auth — Google Sign-In shows
'not configured'" claim against current code turned up that there's no
Google Sign-In step at all anymore, and — more seriously — the onboarding
screen itself was telling every new user *"Your data is encrypted and stays
on this device,"* which is false (encryption was removed in PR #17, over
three weeks before this session). The same screen also described the
removed AI-scanning capability ("we'll read your bills and statements,"
"add cash spends by hand or bill photo"). Fixed all three. Notable: `App.jsx`
already carried a code comment recording that the *database-error* screen
had this exact same "stale encryption claim" bug once before and got fixed
— it just didn't prompt a check of the rest of the codebase for the same
claim. See `findings.md`.

**Pull-to-refresh, root-caused and fixed with partial verification.** PR
#60 had flagged pull-to-refresh as possibly not "arming" reliably,
attributing it to `touch-action: auto`. Traced the actual mechanism:
`Screen.jsx` didn't call `preventDefault()` until after an 8px pull-intent
threshold, giving the browser's compositor several early events to
potentially commit the touch sequence to native scrolling first — after
which a later `preventDefault()` no longer cancels it. Fixed by calling
`preventDefault()` from the first pixel of downward movement instead,
without touching `touch-action` (which risked a much worse regression —
breaking ordinary scrolling app-wide, the exact failure class documented in
the `min-height: 100vh` finding). Built a real headless-browser harness
(Playwright + Chromium via the DevTools Protocol, not a reimplementation)
mounting the actual `Screen` component and confirmed the fix changes
`preventDefault()` timing as intended. Could not get a full end-to-end
confirmation (a completed drag actually triggering `onRefresh`) — traced
this to a CDP/headless-testing limitation around `setPointerCapture()`
that's present on the pre-fix code equally, not something the fix caused.
See `findings.md` for the full investigation.

**Verification throughout:** `npm run build` clean, `npm run lint` at the
same 2 pre-existing baseline warnings, all 43 existing tests pass after
every code change (`src/components/ui/Screen.jsx`,
`src/screens/onboarding/Onboarding.jsx`).
