## What happened

Opened by discovering the OTA update mechanism from Session 03 had **never
actually worked**: the app polled a manifest URL that returned 404,
confirmed on-device, so every "shipped" release since 1.0.4 was never
delivered — only the bundle baked into the APK ever ran (PR #1). The fix
took three iterations to actually land, each correcting the previous one's
wrong assumption: PR #1 published via the newer GitHub Actions Pages
deployment; PR #2 discovered on-device that this repo's Pages is actually
configured as "deploy from branch: main /(root)," which silently ignores
Actions-based deploys, and switched to committing `latest.json` + the
bundle zip straight to `main` root; PR #3 stopped that from committing a
"changed" bundle on every run (builds aren't byte-reproducible) by gating
on `latest.json` content instead of zip bytes. From there: savings goals
got promoted from buried-in-Insights to a first-class Home card + dedicated
screen with pace tracking (#4); a reusable `DetailScreen` pattern was built
for tap-to-open drill-down dashboards, first for categories (#5), then
reused for bill types — EMI/subscription with payoff math (#6) — and smart
patterns (#7). Full theming shipped: light/dark/system + 7 accent colours,
CSS-variable driven so ~290 inline styles re-theme automatically (#8),
immediately followed by a dark-mode bug fix where several "active" toggles
went cream instead of the accent color because they'd used `colors.ink` for
their background, which inverts in dark mode (#9). Smaller polish followed
— transaction time on Home's list (#10), merchant category rules so smart
patterns can auto-file future payments (#11) — then a real bug: restoring a
backup **doubled all SMS-derived data**, root-caused to `sms_log` (the
de-dup memory) never being included in backups (#12) — see `findings.md`.
Closed with a natural-language quick-add bar ("500 groceries") (#13),
budget-vs-actual on the category dashboard (#14), making "Track as a bill"
a real action instead of a dead cosmetic toggle (#15), and "self-healing
updates" — silent auto-restore, removing `sms_log` from backups again
(it had bloated backups enough to freeze restores) in favor of the
already-shipped idempotency guard, and a duplicate-transaction cleanup tool
(#16).

## What the owner asked/reported

| What was asked/reported | Outcome |
|---|---|
| OTA updates were never reaching the phone (confirmed via 404 on the manifest URL) | Root-caused across #1–#3 to this repo's Pages source being "branch: main /(root)," not GitHub Actions deploy |
| Active toggles showed cream instead of the accent colour in dark mode | Root-caused to `colors.ink` inverting in dark mode; switched those toggles to the accent (#9) |
| Restoring a backup, or auto-restoring after an update, doubled income and spending | Root-caused to `sms_log` never being backed up (#12) |
| An app update was resetting the DB → recovery → restore froze → doubled data | Interim symptom-relief shipped: silent auto-restore, un-freeze (drop `sms_log` from backups again), duplicate cleanup (#16) — explicitly **not** the root cause fix, which needed a native build (see Session 06) |
