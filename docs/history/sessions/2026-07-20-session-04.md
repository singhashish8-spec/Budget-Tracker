## What happened

A dense run of fixes and features, still all direct-to-`main`: `5503b2d`
parsed AU Bank's "Dr"/"Cr" SMS format, which had been silently dropped
entirely before this. `6aa4828` fixed the Android back gesture, added
recovery for missed SMS, and corrected de-dup and cycle-total math. `765a026`
made transaction date/time always show, named NEFT senders instead of
showing raw codes, and added search-by-amount. `75eb9a1` added the first
version of **automatic on-device snapshotting with recovery on an empty
database** — the mechanism that everything from Session 05 onward
("self-healing updates," the backup-restore bug, the restore-hang bug)
builds on or fixes bugs within. `f959d54` added backing the JSON snapshot up
to the user's own Google account (shipped as APK v1.1). `5fb8b56` added
manual cash entry for spending and income. `8a4bb97` made transactions,
budgets, goals, and bills editable (previously add-only). `1adf77d` added
budgets with daily pacing, pay-cycle periods, deadlines, and suggested
limits. Version bumps (`9e1fc47`, `1268e6b`, `3e39732`, `4aa1629`, `fe2c548`,
`624e264`) interleave throughout, taking the web bundle from 1.0.3 to 1.0.9.

## What's still pending

- The auto-backup/recovery mechanism introduced here (`75eb9a1`) is
  foundational to the rest of the project's data-safety story — and also
  the mechanism whose *restore* path had multiple serious, separately
  root-caused bugs later (see `findings.md`: the doubled-data bug, the
  hangs-forever bug, the column-mismatch bug). The snapshot mechanism itself
  worked; the restore-from-snapshot path is what kept breaking in new ways.
